EnerLint

A second look at exported mass and energy balances.

Source / README ↗Verification contract ↗

What exists

Independent mass-flow and steady first-law closure for a declared non-reactive control volume; energy accumulation for one storage interval; strict SI JSON contracts; residual thresholds; a command-line interface, Python API and machine-readable evidence reports with an input fingerprint.

The implementation computes residuals separately from the solver's convergence report. It still relies on the exported values, chosen system boundary and declared modelling assumptions.

Results recorded in the repository

4 / 4Hand-constructed reference cases pass
6 / 6Selected deliberately broken cases flagged
1Compensating error that still passes

The 27 October benchmark report records 42 locally passed tests and links one successful CI workflow. These are developer-selected software checks, not fault-detection accuracy on real models.

Reproduce locally 
git clone https://github.com/Open-Energy-Methods/enerlint.git
cd enerlint
python -m pip install -e ".[dev]"
python -m pytest -q
python scripts/run_foundation_benchmark.py

What remains unresolved

No external numerical review, production input adapter, comparison with incumbent solver diagnostics, public PyPI package, GitHub release or DOI. The software does not independently establish that an operating point or property state is correct.

02 / Personal repository · Fortran 2008 · Published source beta

ThermoTwin-F

Gas-turbine and combined-cycle modelling, with the approximations exposed.

Source / README ↗Version DOI ↗

What exists

A Fortran educational simulation framework for Brayton cycles and optional heat-recovery/Rankine extensions, design and degradation analysis, transient response, inverse diagnostics, measurement-uncertainty studies, and grid-related scenario experiments. The native Windows GUI is experimental; it is not a verified distributed executable for the current beta.

Published software record

v2.0.0beta.1, source-only prerelease
10 / 10CI jobs on exact tagged source commit
DOI10.5281/zenodo.23679426

Released 27 October 2026. The immutable GitHub prerelease corresponds to commit ee04616. DOI is an archival identifier, not scientific validation.

A result worth inspecting

Approximate steam properties vs CoolProp IF97

A nine-pressure-point comparison reports 0.532 K saturation-temperature MAE, but 215.854 kJ/kg superheated-enthalpy MAE. These are observed discrepancies of simplified helper correlations against the selected reference, not acceptable performance thresholds.

Reproduce the core build

git clone https://github.com/abhijith-sivaprasadan/thermotwin.git
cd thermotwin
make
make check

Requires a suitable Fortran compiler; check the README for prerequisites. Real plant calibration, IF97 compliance, interactive GUI acceptance and industrial suitability are not established.

OpenSteamOpt

Steam and power scheduling, solved and independently accounted for.

Source / README ↗Verification ↗

What exists

A two-boiler, two-header Modelica plant with a carbon-aware, hourly Pyomo/HiGHS mixed-integer scheduling layer, an FMU co-simulation route using OpenModelica/FMPy, a Python shadow twin and a Streamlit advisory interface. All operational, price and plant parameters are synthetic.

Reproduce locally 
git clone https://github.com/abhijith-sivaprasadan/opensteamopt.git
cd opensteamopt
uv sync --all-extras --frozen
uv run python -m pytest -q
uv run streamlit run app_streamlit.py

What the reference result means

The repository records 28 locally passed tests, zero unmet steam or electricity in optimized reference scenarios and a maximum reconstructed balance residual of approximately 7.11 × 10⁻¹⁵ in the model's accounting units.

No plant calibration, live control connector, real procurement case, safety review, or measured financial/emissions performance is claimed.

Kerala2040

When the observations have limits, the conclusions must have limits too.

Research website ↗Source / README ↗

What the public research record supports

Audited Kerala electricity-consumption statistics, installed generation-capacity records, source-day availability of operational reports, and a retrospective weather–daily-demand analysis using observed SLDC daily targets and ERA5 reanalysis.

29,311.76MU, FY2024–25 official consumer-side annual consumption
354 / 365FY2024–25 SLDC daily source reports available
353Observed daily SLDC targets matched to full ERA5 days

Different denominators, different meanings: the 354 SLDC days sum to 30,666.2569 MU under the operational reporting boundary; this does not replace the 29,311.76 MU annual consumer-side statistical series. Do not directly compare their totals. Read the definitions ↗

A bounded ML finding

Weather helps in most, not all monthly holdouts

One-financial-year retrospective rolling tests: ERA5 features reduced holdout RMSE relative to tuned calendar baselines in 6/7 XGBoost and 5/7 LightGBM months. November 2024 was a shared failure month. The pooled XGBoost weather RMSE was 2.865 MU/day, compared with 4.558 MU/day for calendar-only.

This uses same-day realized reanalysis, not day-ahead forecasting, causal weather effects, multiple years or measured hourly/15-minute operational telemetry. Hourly profiles, hydro and long-term grid scenarios remain exploratory.
